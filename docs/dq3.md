# DQ3対応（0.3.1）

## 対象

PRG 256 KiB、CHR RAM、binjnesの既存MMC1実装で動作。ROMの元ファイルとゲーム側のROM内容は変更しない。
Mapper 2変換版では、末尾に128バイトの付加情報があり、ヘッダーの予約領域が文字列で汚染されている。PRG本体の差は固定バンクのMapper操作21箇所だけで、音声ドライバーとデータは標準版と一致する。
0.3.1ではこの完全一致ハッシュのROMに限定し、メモリ上で付加情報を除去、ヘッダーのRAM容量を8 KiBへ補正する。Mapper 2とPRGの命令変更はそのまま保ち、既存コアのMapper 2で実行する。元ROMと保存ファイルの識別子は変更しない。DQ3の倍速プロファイルを適用する。

## 再利用

DQ4と同じく、既存binjnesのCPU・PPU・APU・MMC1とWiiz由来の音声専用コア方式、ステートのシリアライザーを利用する。新しいエミュレーターや音源は実装しない。DQ3固有の処理は音声要求の取得、原作ルーチンへの接続、入力待ちの補正のみ。

## 音声

音声ドライバーはPRG16 KiBバンク1。更新 `$8000`、通常要求 `$85C1`、別モード要求 `$85AC`、フェード `$8542`、初期化 `$8581`。
`$06F0` 書込時PC `$8675` のスタックから、呼出元 `$85C3`／`$85AE` と保存された要求値を取得する。`$FA` のPC `$854A`／`$85A2` でフェード／初期化を取得する。バンクを確認し、他のゲーム処理の同じアドレスを音声要求と誤認しない。

音声専用側はメモリ上のROMコピーの割り込みベクターを接続コードへ向ける。CPU RAM `$0700` に起動処理、`$0780` にNMI処理、`$0500–$057F` に要求受渡しを配置する。DQ4の受渡し領域はDQ3のドライバー領域と重なるため流用しない。
初期化前に `$06F0=$FF` とし、原作の停止要求が既存曲と同じと判断されて省略されないようにする。これを省くと未初期化のチャンネルを更新してしまう。生成元は `tools/generate_dq3_harness.py`。

ゲーム側はホスト更新ごとに1〜6フレーム、音声専用側は1フレーム進める。1倍で開始したときの音声経路とAndroidのバッファ・非同期保存対策は従来どおり。

## 入力・保存

物理的な長押し状態を元のまま渡す。DQ3のコントローラー読込処理は固定バンクの `$CB25`。`$18/$19` が原作のリピートカウンターで、PC `$CB57` の初回7・反復11への再設定だけを補正する。通常の減算を毎回倍率化しない。共通メニュー描画の待ち時間も含めて補正し、原作の待ち時間と最大1ホスト更新差でカーソル移動することを確認した。1倍では値を変えない。

ステートはゲームと音声コア、要求キュー、速度、補正速度・作品プロファイルを保存する。既存予約領域を使うためコアスナップショットのサイズは変えない。旧形式は読み込めるが、音声専用状態のない旧形式では現在BGMを先頭から再開する。

## 検証

- 1倍の起動、映像・音声、SRAM往復と5枠の保存読込。
- 初期化・停止要求を原作の実行から取得し、音声専用側の出力エネルギーを原作と比較。無音場面の異常な発音がないことを確認。
- BGM・SE・フェードの同一要求列を与え、1〜6倍すべての239616サンプルが完全一致。
- 冒険の書選択画面で上下長押し→解放を繰り返し、原作のカーソル位置 `$75` の8回の移動と間隔が1倍との差最大1ホスト更新。押下状態を含む途中のステート復元後も画面が完全一致。
- 各2〜6倍のステート復元後60ホスト更新の映像・音声が一致。旧形式読込、破損拒否、実行中ゲームの保持。
- SDL入力イベントで4倍へ切替、冒険の書の上下選択、保存・復元、機能メニューを実行。
- DQ4の入力と各速度のステート復元を回帰確認。

記録は `build/dq3-sound-final.log`・`build/dq3-input-final.log`・`build/dq3-state-final.log`・`build/dq3-sdl-final.log`。確認画像は `build/checks/dq3-sdl-final/menu.bmp`。

Android実機のDQ3操作・聴感、全BGM/SEの全尺、冒険の書作成完了後の移動・戦闘・長時間プレイは未確認。音声テーブル全件の検証も未実施。1〜6倍の同一要求比較は、ゲーム全場面での聴感一致を意味しない。


## 0.3.1のクラッシュ修正

旧形式のヘッダー8バイト目は0x69で、PRG RAMを105×8 KiBと誤解釈させていた。0.3.0ではこの版にSpeed: unavailableと表示し、通常実行のコアでもアクセス違反（Windows終了コード0xC0000005）を再現した。既知版の補正後は8 KiBとして動作する。
未知の旧形式ヘッダーでコアの64 KiBを超えるPRG RAMを指定した場合は初期化前に拒否する。補正は既知ハッシュ以外へ広げない。エラー表示中にSDLが破棄されないよう終了ガードの生存範囲も修正した。

確認ログ：`build/dq3-mapper2-fixed.log`（各速度の保存復元）、`build/dq3-mapper2-input.log`、`build/dq3-mapper2-sound.log`、`build/dq3-legacy-sdl-031.log`。標準版の回帰確認は `build/dq3-standard-regression.log`。異常ヘッダーを既知版と誤認しない検査は `build/invalid-header-check.log`。
Androidの実機はadb未接続のため、端末上でのクラッシュ解消は未確認。
